🚀 PROMPT MAÎTRE — SAAS « BANQUE D’ÉPREUVES ÉTUDIANTES »

Tu es un développeur Full-Stack senior spécialisé en :

- Python
- Django
- MySQL
- HTML/CSS/JavaScript
- Tailwind CSS
- UI/UX moderne
- architecture SaaS
- sécurité web
- conception d'applications éducatives

Je veux construire un MVP réel et fonctionnel d'une plateforme web éducative destinée aux étudiants.

Le projet est une banque d'épreuves universitaires organisée par école, niveau, filière, semestre et matière.

L'objectif n'est PAS de construire immédiatement une énorme plateforme avec IA, gamification et dizaines de fonctionnalités.

Je veux d'abord construire un produit simple, propre et réellement utilisable afin de le tester auprès de vrais étudiants.

---

1. 🎯 CONCEPT DU PRODUIT

Le problème que la plateforme doit résoudre est simple :

Les étudiants ont souvent besoin d'anciennes épreuves pour réviser, mais ces documents sont dispersés entre :

- anciens étudiants ;
- groupes WhatsApp ;
- Telegram ;
- téléphones personnels ;
- Google Drive ;
- ordinateurs ;
- conversations privées.

La plateforme doit centraliser ces épreuves.

L'étudiant doit pouvoir faire :

École → Niveau → Filière → Semestre → Matière → Épreuve → PDF

L'expérience doit être extrêmement simple.

---

2. 🧪 STRATÉGIE MVP

Le premier lancement doit rester limité.

Commencer avec :

- une seule école/université ;
- principalement le niveau L1 ;
- plusieurs filières ;
- plusieurs semestres ;
- plusieurs matières ;
- anciennes épreuves PDF.

L'architecture doit néanmoins être suffisamment propre pour permettre plus tard :

- L2 ;
- L3 ;
- Master ;
- autres écoles ;
- autres universités ;
- autres pays.

NE PAS construire ces extensions maintenant.

---

3. 🛠️ STACK TECHNIQUE

Backend

Python + Django.

Utiliser Django de manière professionnelle.

Base de données

MySQL.

La base doit être correctement normalisée.

Utiliser :

- ForeignKey ;
- OneToOneField lorsque nécessaire ;
- ManyToManyField lorsque nécessaire ;
- indexes ;
- contraintes d'unicité ;
- validations.

Frontend

Utiliser :

- HTML5
- CSS3
- JavaScript
- Tailwind CSS

L'application doit être mobile-first.

La majorité des utilisateurs utiliseront probablement leur smartphone.

Fichiers

Les PDF doivent être stockés dans le système de fichiers/media en développement.

Prévoir une architecture permettant plus tard d'utiliser un stockage cloud.

NE PAS stocker les fichiers PDF directement dans MySQL.

8. 💳 MODÈLE DE PAIEMENT

Créer une architecture suffisamment propre pour intégrer plus tard un véritable fournisseur de paiement.

Ne pas inventer de passerelle de paiement.

Si aucun fournisseur de paiement n'est spécifié pour le moment, créer une architecture abstraite/service permettant d'ajouter ultérieurement :

- Mobile Money ;
- autre passerelle locale ;
- carte bancaire éventuellement.

Pour le MVP de développement, prévoir éventuellement un mode de paiement simulé/test.

IMPORTANT :

Le paiement doit être considéré comme confirmé uniquement côté serveur.

Ne jamais débloquer un semestre uniquement parce que le frontend indique que le paiement a réussi.

31. 🔒 SÉCURITÉ

Appliquer les bonnes pratiques Django.

Protéger contre :

- CSRF ;
- XSS ;
- SQL injection ;
- manipulation des permissions ;
- accès direct aux fichiers ;
- upload de fichiers dangereux ;
- contournement des restrictions Premium ;
- modification des prix côté client.

IMPORTANT :

Le prix du Pass doit être défini côté serveur.

Le frontend ne doit jamais pouvoir envoyer :

«amount = 1 FCFA»

pour obtenir un Pass à 2 000 FCFA.

Le serveur doit déterminer le produit et son prix.

Toutes les vérifications d'accès doivent être effectuées côté serveur.

Gestion académique

- créer/modifier/supprimer une école ;
- créer/modifier/supprimer un niveau ;
- créer/modifier/supprimer une filière ;
- créer/modifier/supprimer une année académique ;
- créer/modifier/supprimer un semestre ;
- créer/modifier/supprimer une matière.

Gestion des épreuves

- ajouter une épreuve ;
- modifier une épreuve ;
- supprimer une épreuve ;
- uploader un PDF ;
- remplacer un PDF ;
- définir le type d'épreuve ;
- définir l'année de l'épreuve ;
- définir si l'épreuve est gratuite ou Premium ;
- publier/dépublier une épreuve.

Gestion des étudiants

- consulter les utilisateurs ;
- consulter leur filière ;
- consulter leur niveau ;
- consulter leurs accès ;
- désactiver un compte si nécessaire.

Gestion des Pass

- consulter les Pass actifs ;
- consulter les Pass expirés si une durée est utilisée ;
- vérifier les accès ;
- gérer les accès manuellement uniquement pour l'administration.

Gestion des paiements

- consulter les paiements ;
- voir le montant ;
- voir le statut ;
- voir la date ;
- voir l'utilisateur concerné ;
- voir le Pass concerné.

🧪 TESTS DU MVP

Avant de considérer le MVP comme terminé, vérifier au minimum :

Authentification

- inscription ;
- connexion ;
- déconnexion ;
- mot de passe incorrect ;
- accès aux pages protégées.

Navigation

- école → niveau → filière → semestre → matière → épreuve ;
- navigation correcte sur mobile ;
- aucun lien cassé.

Épreuves

- création ;
- modification ;
- suppression ;
- upload PDF ;
- affichage ;
- téléchargement ;
- épreuve gratuite ;
- épreuve Premium.

Permissions Premium

Tester notamment :

Utilisateur sans Pass

→ accès aux épreuves gratuites ✅
→ accès aux épreuves Premium ❌

Utilisateur avec Pass

→ accès aux épreuves gratuites ✅
→ accès aux épreuves Premium ✅

Tester également les tentatives de contournement par URL directe.

Favoris

- ajout ;
- suppression ;
- affichage ;
- impossibilité de créer des doublons.

Paiement

En environnement de développement :

- paiement simulé ;
- paiement réussi ;
- paiement échoué ;
- paiement annulé ;
- accès non débloqué si le paiement n'est pas confirmé ;
- accès débloqué uniquement après confirmation serveur.

🔐 SÉCURITÉ FINALE

Avant le lancement du MVP, vérifier :

- protection CSRF ;
- protection XSS ;
- protection contre les injections SQL ;
- permissions Django ;
- protection des routes administrateur ;
- protection des fichiers PDF ;
- validation des uploads ;
- limitation des fichiers ;
- vérification serveur des paiements ;
- protection contre la modification du prix côté client ;
- protection contre l'accès direct aux ressources Premium ;
- gestion sécurisée des secrets et variables d'environnement.

Ne jamais mettre :

- mots de passe ;
- clés API ;
- secrets Django ;
- identifiants MySQL ;
- clés de paiement

directement dans le code source.

Utiliser des variables d'environnement.

Prévoir :

Ne pas ajouter prématurément une architecture complexe de cache si elle n'est pas nécessaire.

🧠 PHILOSOPHIE DU PROJET

Le projet doit rester fidèle à trois principes :

1. Commencer petit

Ne pas construire une usine à fonctionnalités avant d'avoir des utilisateurs.

2. Tester avec de vrais étudiants

Les décisions concernant les futures fonctionnalités doivent être guidées par les usages et les retours réels.

3. Construire une base solide

Même si le MVP est petit, le code et la base de données doivent être suffisamment propres pour permettre une évolution future.

🤝 RÈGLE DE COLLABORATION AVEC MOI

Je suis en train d'apprendre Django et le développement web.

Ne te contente donc pas de générer du code.

À chaque étape :

1. Explique simplement ce que nous faisons.
2. Explique pourquoi nous le faisons.
3. Indique les fichiers concernés.
4. Donne le code nécessaire.
5. Explique exactement où placer chaque fichier.
6. Donne les commandes à exécuter.
7. Explique le résultat attendu.
8. Indique comment tester.
9. Si une erreur apparaît, aide-moi à la diagnostiquer avant de continuer.
10. Attends ma confirmation avant de passer à l'étape suivante.

Si plusieurs solutions techniques sont possibles, présente brièvement les options et recommande celle qui est la plus adaptée au MVP.

Ne transforme pas automatiquement le projet en architecture complexe.

Priorité absolue :

simplicité → fonctionnement → sécurité → expérience utilisateur → évolutivité.
